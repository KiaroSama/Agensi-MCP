# Rust Migration Contracts

Native Rust2.x replaces the Node runtime while preserving schema1 route/profile state, additive import,
redacted status, new-package-only inline installation and fail-closed routing. PowerShell remains the
launcher/menu/registration adapter. No Rust process invokes Node.

## Native tooling migration

The remaining eight Python runner, release-policy and fixture files are replaced by Rust targets.
`check-run` is a separate developer tool; the downloadable MCP executable remains `agensi-mcp`.
PowerShell launchers and registration adapters are unchanged. No language-statistics exclusion hides
source files. The original tooling remains recoverable at commit
`309052d64a5c205b906c6ee719e7816b32c9a365` for rollback.

| Bounded subprocess guard | `tools/check/`, `check_runner`: 18 named byte/progress/deadline/ownership/logging contracts |

| Published operator guidance | `operator`: six static contracts, not an agent-effectiveness benchmark |
| Native Windows menu | `menu`: six actual redirected-input/EOF/alias/status contracts |
| Independent OAuth/MCP loopback fixture | `tests/audit/`, `audit_blackbox`: 98 CLI/wire/filesystem contracts |

`tests/fixtures/audit-inventory.json` was extracted from the successful source CI run 38399416532,
artifact 11812889295, on the pinned commit above. It guards exact case identities, not just the count.
The independent harness launches a copied executable with synthetic state and a private loopback CA;
it does not replace black-box observations with calls into the runtime implementation. The original98
identities/order remain unchanged. A separate extension inventory defines eight current sign-in/stdio
shutdown controls and four dedicated native-platform TLS-proxy controls; reports validate the two inventories
independently and distinguish historical versus extension counts. New controls are implemented but
not certified by historical CI receipts; consult the exact current run's reports.

Observable parity is byte-exact for child output and structural for JSON. Ordered fixture lists remain
ordered. Timestamps, execution IDs and process IDs are nondeterministic. Rust errors use sanitized
language-neutral status rather than Python exception-class names. Release manifests use the maintained
TOML parser, including standard TOML 1.1 syntax in addition to the source parser's TOML 1.0 syntax.
Invalid package versions and malformed or duplicate-key manifests still fail; no manifest regex or
second interpreter substitutes for parsing.

Developer commands and project-local Cargo/temp setup are in [Tests and CI](../README.md#tests-and-ci).
Bootstrap `check-run`, copy it into `.tmp/` before Cargo reuse (required on Windows), and precompile
all targets under the compile budget. The [workflow target mapping](../.github/workflows/ci.yml)
is authoritative: ordinary libtest targets receive `--test-threads=2`; custom `check_runner`,
Windows-only `menu` and Linux-only `audit_blackbox` run separately with their own arguments.
Release-policy/script fixtures share the ordinary 180/45 execution budget, not a compilation budget.
Use `.exe` runner paths on Windows. Do not run a heavy suite locally merely to duplicate hosted CI.

CI precompiles all targets, then selects ordinary tests separately from the Windows-only menu and
Linux-only black-box harness. A Cargo metadata coverage guard rejects an unmapped test target.
Do not use `cargo test --all-targets` to execute the platform-specific custom harnesses without their
required arguments. Optimized release builds explicitly select `--bin agensi-mcp`; test tooling is
not added to downloadable archives. Production traffic, paid actions and real-account state are not
replayed by this tooling-only migration. CI results, not source translation alone, determine readiness.

## HTTPS-proxy trust verification scope

The dedicated `audit_blackbox --phase=tls-proxy` implements four separately ordered extension cases:
trusted TLS proxy → CONNECT → trusted TLS origin, untrusted proxy, untrusted origin and an observable
no-direct-fallback refusal with a live origin observer. Each native CI platform runs this phase once
through `scripts/test-tls-proxy-ci.ps1`, with owned wall/idle guards, and retains sanitized results plus
cleanup status. The default `all` phase retains original98 cases plus its separate OAuth/runtime
extensions and excludes these dedicated TLS cases. Implementation is not a passing result: inspect
actual final exact-SHA hosted reports before claiming all-platform parity.

The manual workflow's `native_diagnostics` input defaults to false. When explicitly enabled on the
reviewed repair branch, it runs only native TLS-fixture and macOS signature investigation. Those
partial jobs never publish or establish full acceptance; ordinary validation and release still
require the complete non-diagnostic workflow.

The wrapper permits temporary fixture trust, name mapping and network restrictions only on disposable
GitHub-hosted runners, then removes its owned changes. No workstation trust/network settings or real
proxy/account traffic are involved. Ordinary four-platform TLS unit tests are not a substitute for
these actual CLI proxy/origin observations or successful cleanup. macOS rejects changes to its
protected administrative trust authorization right. No authorization-policy workaround is used.
The hosted-only native helper creates an owned temporary administrator with a memory-only random
password in an isolated security session. Cached preauthorization is not a supported cleanup route:
Apple's hardcoded administrative rule has zero credential-cache lifetime. The hosted-only capability
experiment requests the public graphics-session attribute and uses the runner image's existing
osascript Accessibility/System Events consent for genuine SecurityAgent authentication. A worker
receives only the owned temporary credentials through stdin and accepts exactly one native prompt
containing the unique invocation executable name. It never grants permissions, changes TCC or
accepts unrelated dialogs. Missing graphics, consent or an unambiguous prompt fails closed before
fixture trust changes. The worker is bounded/reaped, acquired authorization is destroyed and exact
account/membership removal is checked, including error recovery. Actual hosted results must prove
this route; implementation is not a successful cleanup claim. Runner disposal is not explicit
cleanup. Account failures expose only fixed operation labels
and numeric native status, never credential payloads. Only sanitized helper logs are handed back to
the artifact uploader; private recovery journals retain root-only ownership. No workstation account
or policy is changed.

## Runtime evidence and limits

A native read-only probe through the user's existing selected proxy discovered20 actual upstream tools
and completed an account-scoped read using safely imported legacy session metadata. No credential or
account payload is logged. This is not a purchase, Creator readiness claim or four-client loading test.

Manual OAuth uses current maintained SDK metadata/scopes/PKCE/state/issuer handling, our explicit
selected-route HTTP client and persistent credential-store seam. Stored receipt time is preserved;
legacy data is copied only when public-client, issuer, scope and expiry metadata are compatible, and
old files remain unchanged until the user-authorized final cleanup.

## Reviewed runtime invariants

OAuth retains the complete selected-route owner, including the SOCKS4 USERID adapter. Auth,
HTTP startup, stdio, probes and diagnostics derive clients/change detection from one bounded
settings snapshot and reject stale results. Callback headers are complete/bounded and require one
exact loopback Host in both supported HTTP versions; state, issuer and PKCE remain mandatory.
Native state reads are limited to 1 MiB and refuse linked/reparse/nonregular files before opening.
Accepted root skill entrypoints are written as literal `SKILL.md` for Unix portability.

Windows registration honors the selected Code profile and explicit target paths, validates both
32 MiB-bounded client documents, stages private outputs and verifies read-back. Caught partial
publication is compensated only while bytes remain operation-owned; concurrent/unknown writes
retain recovery evidence. This is not power-loss/crash atomicity. See the [integration ledger](audit-supplement-2026-10-12.md)
for original findings, regression mapping, exact validation requirements and remaining limits.

## Diagnostic and cleanup extensions (2.1)

Local `doctor`, `network-check` and preview/apply `cleanup` supplement the native CLI without altering
Agensi's tool list or its account permissions. Their projection tests exclude credentials and distinguish
missing DNS observations from success. Network diagnostics derive both selected configuration and
change-detection identity from one captured byte read; a subsequent profile change invalidates that
snapshot rather than accepting a different selected route. Runtime commands hold a shared lease; destructive legacy
cleanup takes an exclusive nonblocking lease and refuses linked/reparse or protected subtrees.
Uncoordinated build caches and shared temporary files remain skipped. The cleanup contract is
cooperative process coordination, not protection against malicious noncooperating filesystem swaps.

No cutover claim is valid with unsupported required proxy/auth behavior or unverified native entry.
Unit/source parity does not substitute for real integration. Private production traffic/billable calls
are not replayed. New defaults/error handling cannot silently weaken secure behavior to match a defect.

## Private release-signing contract

A completed release build (omit `-Debug`/`--debug`) requires PowerShell7.4+, approved encrypted leaf
signing inputs and the matching pinned public identity. It embeds the checkout commit, signs and
verifies before replacing the installed binary; missing signer or verification failure preserves the
old installation. macOS private signing runs only on the approved disposable hosted runner; normal
users should use verified release downloads. No compiler, root trust, paid account or signing-key
installation happens automatically. The registration/menu runtime retains its existing PowerShell7.0
floor; only new signing/verification tools require7.4.

Signing tools write one UTF-8 UTC structured log per invocation under `logs/` with INFO/ERROR status,
no passwords or key data. Native macOS codesign failures include a bounded, redacted public diagnostic;
protected keychain command input/output is never included. Logging-init failure falls back safely to stderr;
there is no automatic retention deletion. Close handlers on completion, review logs locally and attach
only sanitized status for support. Private inputs are encrypted locally, passed only to necessary
same-repository manual signing steps, and removed from child process environments. The private root
key never enters CI. Certificate rotation is a separately reviewed operation.

Obtain the public signing files and verification scripts from a separately trusted checkout at the
release commit; confirm the leaf/root fingerprints in `signing/identity.json` through that channel.
A public key from the same untrusted download alone does not establish identity. Download each
archive and checksum together with their `.sig` files. PowerShell7.4+ verifies bytes before extraction:

```bash
pwsh -NoProfile -File scripts/verify-release.ps1 -Path ./agensi-mcp-windows-x64.zip
pwsh -NoProfile -File scripts/verify-release.ps1 -Path ./agensi-mcp-windows-x64.zip.sha256
```

After extraction, verify `bin/agensi-mcp.exe` with `-Platform windows-x64` (or the appropriate Unix
filename/platform), `-SourceCommit` equal to the exact release SHA and `-Version 2.1.6`. The verifier
checks detached bytes, public-key/leaf/root pins, code-signing purpose and certificate validity.
Windows additionally requires native Authenticode file-binding success plus CMS/private-chain checks;
macOS requires certificate-backed, non-ad-hoc codesign with an exact signer requirement. Linux uses
pinned RSA3072/SHA256/PKCS1 detached signatures. Only after acceptance does verification execute doctor
to compare publisher KiaroSama, version and embedded source commit. Archive BUILD-INFO records agree.

This private self-signed CA is not public trust, Apple Developer ID/notarization or a trusted timestamp.
OS warnings can remain. Never install a root certificate or disable OS protections merely to silence
them. Expired certificates fail closed; no timestamp-based post-expiry assurance is claimed.
The four-platform manual release gates and wrong-key/signer/covered-byte controls must actually pass
before publication; implementation alone is not evidence that signing succeeded on macOS or CI.
