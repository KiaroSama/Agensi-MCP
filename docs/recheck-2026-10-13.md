## Finding R1 — P2: output is treated as UTF-8 newline-framed records

**Location:** `scripts/run-check.py`, process creation and `consume`/progress handling in the baseline.

**Root cause:** `Popen(..., text=True, encoding='utf-8')` and iteration over text lines deliver no progress event until a newline or EOF. A healthy command flushing bytes without a newline can exceed the idle deadline. The same reader throws `UnicodeDecodeError` for non-UTF-8 output, terminates its thread, and reports the same completion sentinel as ordinary EOF. The runner can then return the child's zero exit status while silently losing its output. In addition, an unbounded queue and unbounded line assembly let output size determine memory usage.

**Executed reproductions:** a child flushing one byte every 0.1 seconds to stdout or stderr was killed by the 1-second idle limit despite ongoing output; a successful child emitting `begin`, byte `0xff`, and `end` lost the whole output on each stream. These are separate scenarios within one output-reader repair, not four unrelated defects.

**Implemented repair:** use binary subprocess pipes and `read1()` chunks of at most 16 KiB; preserve bytes through `sys.stdout.buffer` without decoding or newline translation. Both child streams retain the existing combined-output convention. Record activity for each delivered chunk. The pending queue has 64 slots, limiting its queued payload to 1 MiB plus bounded reader/consumer buffers. A typed reader-error event is different from EOF and fails the check without including exception payloads. Timed queue insertion observes a stop event, so a saturated queue does not prevent cleanup. The stop event is set before terminating owned processes and joining readers. Windows' bootstrap-before-Job-assignment protocol and Unix process-group cleanup are retained. Job closure is now a cleanup backstop even when termination verification raises.

**Acceptance:** newline-free progress succeeds on both streams; arbitrary bytes and a split multibyte sequence survive exactly; a 2 MiB unterminated output succeeds without truncation; actual idle and wall deadlines still fail; nonzero exit status propagates; inherited-pipe and exited-parent descendants are reaped. Unit controls exercise a saturated queue and a reader I/O exception. Do not substitute `communicate()` with unlimited accumulation, increase child idle deadlines to hide the defect, decode with silent loss, or suppress reader exceptions.

## Finding R2 — P2: nonfinite deadline values disable a requested bound

**Location:** `scripts/run-check.py`, argument parsing.

**Root cause:** accepting unrestricted floats and testing only `min(wall, idle) <= 0` allows `NaN` and positive infinity. Comparisons involving these values do not enforce the intended finite time limit. This is invalid-configuration acceptance, not an allegation that a current workflow already supplies malicious bounds.

**Executed reproduction:** for each field, `nan` and `inf` launched a synthetic marker-writing command and returned normally. No infinite process was required to demonstrate that validation failed.

**Implemented repair:** the argparse type requires `math.isfinite(number)` and `number > 0`, before logging setup or process creation. Keep fractional positive bounds supported. Tests cover NaN, positive/negative infinity, zero and a negative value for both options and prove the child marker is never created.

## Finding R3 — P3: the new Python logger follows a linked log directory

**Location:** `scripts/run-check.py::configure_logging`.

**Root cause:** the Python runner's logger did not inherit the native logger's link/reparse protection. Creating a fresh file through a pre-existing `logs` link wrote outside the intended project directory. The additional close/reopen sequence also unnecessarily discarded ownership of the exclusively created descriptor.

**Executed reproduction:** an isolated project with `logs` pointing to a separate fixture directory created a log in that target. No real user path was involved. The logs contain structural status, not command arguments or credentials; this finding does not claim a demonstrated credential disclosure.

**Implemented repair:** inspect the directory and ancestors with `lstat`, reject symbolic links and Windows reparse points, and repeat the cooperative check after directory creation. Open the unique log exclusively with Unix mode `0600` and `O_NOFOLLOW` where available; keep the descriptor in an owned handler rather than reopening the path. The timestamped console handler remains active on file failure. Support INFO, WARNING, ERROR and DEBUG; `--debug` enables detailed safe runner diagnostics. Never log the command argument vector or child output in the runner's own status file. The console still intentionally relays the child process's output, so callers must run checks whose output is suitable for CI disclosure.

**Acceptance:** a symlink fixture on Unix and a junction fixture on native Windows receive no outside file; safe stderr fallback preserves successful command execution; four-level logs retain timestamps and omit the synthetic private-payload marker; Unix file mode is `0600`. These are cooperative path checks, not a claim of a race-proof hostile-filesystem sandbox.

## Finding R4 — P2 EOF loop; P3 missing advertised menu alias

**Location:** `run.ps1`, main menu input and switch.

**Root cause:** an empty selection maps to the default import operation, but the input path did not distinguish redirected end-of-input from a user pressing Enter. Repeated EOF can therefore repeatedly enter the default operation rather than terminate. The prompt also advertises `quit=exit`, but the switch accepts only `exit` and `0`.

**Implemented repair:** when input is redirected, use `Console.ReadLine()` and treat its null EOF result as a clean exit. Keep an actual empty string mapped to menu item 1. Preserve interactive `Read-Host` behavior. Add the advertised `quit` alias without removing `exit` or `0`. Emit a safe timestamped menu status at EOF.

**Acceptance:** `scripts/test-menu.py` runs only on native Windows with the freshly built Windows executable, an isolated project root and disposable configuration. Six test methods cover `quit`, existing aliases, immediate EOF, invalid selection followed by EOF, a real blank-line default import using a synthetic proxy profile, and unchanged machine-readable `-Status` JSON. Every child has a deadline. No test authenticates, connects to a production proxy, edits real client configuration or performs a marketplace operation. The source-level defect was identified here; native Windows execution is established by this PR's own CI evidence, not claimed as a local Linux PowerShell run.
