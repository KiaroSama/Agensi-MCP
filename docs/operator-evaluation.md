# Operator Evaluation

## Method

2026-10-10: two fresh host subagents received the same three immutable synthetic fixtures in `tests/fixtures/operator-tasks.json`. One additionally read the operator guidance and routed references; the other was asked for competent ordinary-agent answers without skill access. Neither received project research/history or the other answer. Both produced actual answers, not a reused offline walkthrough. No external action, purchased content, buyer contact or financial input was involved.

The native Claude CLI was unauthenticated (`loggedIn:false`), so native `claude plugin eval`/trigger testing could not run. Direct guidance use in a host subagent is not native plugin loading. This experiment covers bounded output quality, not cloud service/runtime integration or a commercial benchmark.

## Predeclared outcome criteria

- Offer selection: specific buyer/input/artifact; competent free alternative; confounded uptake rather than sales; bounded comparison/holdout; no publication/action.
- Draft improvement: explicit fields, preserved rows/IDs, missing values/exceptions, duplicates, separate currencies, draft-only authority and meaningful failure checks.
- Metrics/readiness: no monthly-delta inference, no install-based earnings, readiness unknown after profile failure, selected proxy preserved, no diagnostic submission.

Each criterion is inspected against produced text/artifacts, not mere Skill invocation. A correct baseline is credited. Critical safety/factual failures are not averaged away.

## Actual result

Both outputs met the core correctness/permission criteria. The baseline already produced a strong input/output and financial-integrity contract. The skill-assisted answer additionally made the synthetic nature explicit, separated proposed edits from actual execution, provided more direct holdout/near-miss coverage, and tied a differentiation chain from evidence to artifact/check/rollback. These are observed differences in one paired sample, not proof of statistical or commercial superiority.

**No positive effectiveness lift is established:** no repeated trials, blind independent graders, actual repository upgrades or real expense exports were run. More detail is not automatically more value. A 25% time-saving threshold suggested by the baseline is an untested proposed target, not an observed improvement.

## Demand validation

The user's requested substitute for buyer/payment testing was public competitor analysis. Fresh matched comparisons for incident reviews, datasets and editable implementation showed stronger uptake alongside low-uptake same-job alternatives. The original competitive-validation reference extracts artifact, narrow-job, baseline, setup and trust hypotheses with counterexamples. Public installs do not establish paid sales, realized price, conversion, revenue or why a particular offer won. No customer willingness-to-pay experiment occurred.

## Reproducibility and limits

Use the tracked fixture with a healthy authenticated isolated runner and the same model/tools/budgets for both arms; test discovery separately from outcome. The fixture is synthetic and proves only its structure. Native loading of all four clients, real private-file scenarios and actual payment/retention remain untested. Do not use these results as advertising claims, safety certification or guaranteed sales evidence.
